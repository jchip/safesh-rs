Should safesh become a Rust bash runner?

The new safesh would be a non-interactive bash runner written in Rust. It parses bash and runs commands directly, with permissions and sandboxing built in. It drops the transpile to TypeScript and reuses existing code wherever it can.

The short answer
Worth it: yesIt removes the layer that causes most of today's bugs.
Reuse brushA Rust bash engine with an exec hook already exists. Embed it.
Sandbox at OS levelA shell can't see what its children run. The kernel sees all of it.
1 · Where safesh is today

Two paths, and neither one is sandboxed by the OS

~40klines of TS that emulate a shell: parser, transpiler, coreutils
~1 in 3commits since June are bash emulation fixes (40 to 55 of 156)
0lines of Seatbelt or Landlock code. The OS sandbox exists only in design notes.
2 · What agents actually write

Plain bash: pipes, chains, loops and heredocs. Almost no zsh.

From 541 local Claude Code transcripts. Commands run under zsh on this Mac, yet agents write bash and POSIX. Edge cases to test: unquoted $var word splitting (22 uses), <( … ) (92 uses) and unmatched globs.

3 · Where today's bugs would go

Most bug classes disappear, and the rest move to a shared engine

Counts are about 135 bash fixes from six months of git history, taken from the June architecture review.

4 · What we reuse

We write the glue. Others already wrote the shell and the sandbox.

Matching bash costs years. Oils spent 9+ years on it, and brush runs 2,500+ test cases against real bash. Reusing brush means that work is already done.

5 · What owning the interpreter buys

Exact argv at exec time, so the policy never has to guess

Every external command in brush-core goes through one ProcessLauncher trait. Its docs name sandboxing as a use case. Loops, $( ), pipelines and subshells all run in-process and share that one gate.

0lines to patch in brush. The hook point is a public trait.
1live Shell object per session, holding cwd, env and vars. No state-marker round trip.
126exit status when the launcher denies a command, as in bash
6 · Why the OS sandbox is still required

A shell only sees the first exec, but agents spawn whole process trees

The hook gives good prompts. The sandbox gives real safety. We need both.

7 · Recommended shape

Three layers, each doing one job

8 · Risks
brush is 0.xThe API can change between releases.Pin the version. Wrap it behind one adapter module.
~470 known failuresbrush marks about 470 of its 2,500 test cases as failing.Run our field-issue corpus in the spike. Fix gaps upstream.
Writes without exec> file, cd, source and mapfile skip the launcher.Add a redirect and builtin gate. The sandbox catches the rest.
Wrapper programsbash -c, xargs and find -exec hide the real command.Add rules for wrappers, as safesh has today. The sandbox is the backstop.
Stateful launcherThe trait requires Default, so passing policy in needs care.Use a shared Arc. Confirm in the spike that brush accepts a launcher instance.
TS mode/*#*/ TypeScript and the Deno stdlib don't fit a Rust runner.Your call: keep Deno for TS mode only, or drop it.
9 · Plan with exit points

Prove it on real commands before porting anything

P0

Hands-on spike needs your OK

Build brush. Write a PolicyLauncher prototype. Replay our field-issue corpus through brush and bash, then compare.

Exit point: brush matches bash on most of the corpus, and the hook catches rm in loops, $( ), $x and eval.

P1

Rust runner behind a flag

brush plus the policy launcher plus Seatbelt. The current hook sends the transpile path to it when a flag is on. Policy is read from today's config files.

Exit point: daily use for a few weeks with fewer bug reports than the transpiler.

P2

Make it the default, retire the transpiler needs your sign-off

Port policy and approvals to Rust. Delete about 40k lines of emulation. This changes existing behavior, so the migration plan is yours to approve.

Exit point: approvals and the retry flow work across Claude Code, Codex and agy.

P3

Linux sandbox and upstream fixes

Add Landlock and seccomp. Send brush fixes upstream. The maintainer has an open "safer shell" issue and seems open to this use case.

Exit point: the same corpus passes on Linux.
