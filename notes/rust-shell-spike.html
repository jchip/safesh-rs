safesh-rs · design · 2026-11-05

safesh in Rust: a bash runner with a guard at every exec

The new safesh is one Rust binary. It runs agent bash commands directly on a reused bash engine. A Deno-style policy checks every command and file write before it happens.

Real bash enginebrush runs the script. No more transpiling to TypeScript.
Guard at the exec pointEvery command and redirect is checked. The environment stays open.
Deno-style policyOne policy core, reusing Deno's own permission crate.
1 · Why change

Today safesh emulates a shell, and the emulation keeps breaking

~40klines of TS that emulate bash: parser, transpiler, coreutils
~1 in 3commits since June are bash-emulation fixes
29 msDeno start before desh does any work
2 · What agents actually write

Plain bash: pipes, chains, loops and heredocs

From 541 local Claude Code transcripts. So the target is bash, not zsh, and non-interactive only.

3 · The new flow

Check up front, then run in a real engine that checks again

The pre-check catches almost everything before any side effect. The runtime gates catch what static analysis can't know, like x=$(pick); $x. A runtime denial stops the script with exit 126 and the usual retry hint.

4 · The policy core

One core, like Deno. Checks never spread through the code.

Denosafesh
ops call permissions.check_*()exec and open gates call the policy core
PermissionsContainer in every opone shared policy inside the launcher
typed descriptors, deny always winsthe same, reused from deno_permissions
PermissionPrompter traitResponder: hook, runtime or test mode

safesh's config was built on Deno's --allow-read/write/run flags, so path decisions keep parity with today.

5 · What it covers

A guardrail inside our shell, not a jail around the machine

Caught (spike verified)

  • rm in loops, $( ), pipes, functions
  • x=rm; $x, eval, exec
  • nested bash -c, sh s.sh
  • > and &> outside allowed paths
  • touch, mv ../ outside allowed paths
  • git push --force

Planned (P3)

  • xargs rm
  • find -exec rm
  • env, timeout, nice wrappers
  • sudo always asks

Outside, by design

  • make recipes
  • Python os.remove
  • npm run scripts, git hooks
  • anything a program does without our shell

No OS sandbox. You chose a fairly open environment with restraints at the command point.

10 · Decisions
Dialectbash, non-interactive
Engineembed brush-core; nested bash -c re-runs safesh
Enforcementexec and open gates into one Deno-style core (D6)
OS sandboxnone
Postureallowlist plus prompt, as today, with argv rules on top
Commandschecked by resolved path, not just name (D2)
Sessionsgrants keyed by the hook session_id (D3); one 1-5 choice numbering (D4)
ConfigJSON only, plus a one-time config.ts converter
